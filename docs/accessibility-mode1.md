# 模式一：本地路网时间扩展等时圈

## 论文依据及实现范围

王秋菊、李毅军《基于百度API的轨道站点步行可达范围识别方法》（2024），第 203 页提出：米制投影、30 m 点阵、为 OD 点计算出行时间、TIN 插值及等值线提取。

何亚坤、艾廷华、余文豪《等时线模型支持下的路网可达性分析》（2014），第 1191–1193 页提出：沿网络拓扑扩展，加载通行方向、道路等级、出行速度和时间分段约束，再提取边界；直接凸包会包含过多不可达空白区域，嵌套等时线应保持时间次序。

本实现借鉴两篇的时间成本、拓扑约束、米制点阵和时间分区思想。以本地 OSM 的 Dijkstra 最短时间替代百度 OD API，以规则时间场分类、栅格矢量化替代 TIN 及扩展凸包/角平分线移位。**这是可运行的工程改编，未宣称复现两篇论文的全部算法。** 百度 API 模式、实时交通、TIN 插值和何文的具体水流栅格扩展/移位算法均未实现。

## 数据与拓扑

- 从 `01_交通网络/01_道路路网/gis_osm_roads_free_1.shp` 读取原始线几何，不能使用已经简化的地图展示道路来构图。
- 在 WGS84 / UTM zone 50N（EPSG:32650）中计算米制长度、投影到线的位置和面积。前端与导出使用 EPSG:4326。
- 在原始线共享的顶点处分边，以毫米坐标舍入匹配节点。不根据平面几何交叉强行连接，避免将桥梁、隧道与下方道路误接。不同坐标的近接断头点不会自动修复。
- 路网保留武汉市界外 5 km 上下文，允许短路径出界后再进入；起点必须在武汉内，圈面裁剪到市界。接近数据上下文边缘时结果仍可能截断。
- 源数据缺少完整 `access`、`foot`、`bicycle`、转向限制和设施入口字段。因此按道路类型近似允许通行，属于静态网络模型，并非导航级路线或实际出行承诺。

## 时间成本与搜索

每条边的通行成本为 `c(e) = length_m(e) / speed_m_per_s(e)`，单位为秒；沿几何长度计算，不以两个端点间直线长度代替曲线长度。

步行允许双向，排除 motorway/trunk 及连接线，台阶速度乘 0.65。骑行排除 motorway/trunk、连接线和台阶，遵循一般单行方向，土路和小径速度乘 0.65；缺失的自行车逆行豁免尚不支持。驾车排除步行道、步行街、台阶、小径、自行车道和骑马道，遵循单行方向。

驾车以道路等级默认速度（高速 80、快速路 60、主干路 50、次干路 40、三级路 30、居住路 25、生活街道 10、服务道路 15 km/h）乘 `界面基准速度 / 35`，并以有效 `maxspeed` 为上限。界面基准速度不是每一条路的实际行驶速度。未建成、废弃及赛道等不参与分析。

起点搜索 200 m 内符合方式的道路，投影至路段中部；起点到道路的接入按 `min(当前速度, 5 km/h)` 步行计时。普通接入线不能跨越本地已映射水域。没有合法接入或预算不足时返回错误。

起点作为临时的路段内发生元，按方向向两个端点初始化距离。Dijkstra 使用最小堆，扩展到时间预算即停止。对于道路上的位置 `s`，根据方向取下面的有效最小值：

```
tau(s) = min(d(u) + s/v, d(v) + (L-s)/v,
             初始接入时间 + abs(s-起点投影位置)/v [仅起点所在边])
```

时间终点位于路段中部时精确截断；双端可达产生的重叠区间合并后再计算长度，避免重复统计同一条边。

## 时间场与圈面

1. 从最大阈值可达路段的范围生成默认 30 m 网格。大范围分析适当增大网格，使采样单元约不超过 30 万；返回实际 `gridMeters`，界面也显示该值。若所需网格大于 120 m，则在耗时面化前返回范围过大的提示，要求缩短时间或降低速度。
2. 为每个格心查找 90 m 内可接驳的路段，计算 `格心时间 = tau(路段投影位置) + 接驳距离 / 步行接驳速度`，在候选路段中取最小值。不是把一个欧氏圆当成等时圈。
3. 接驳线与本地水域相交时剔除；桥梁中心线附近 8 m 内允许保留桥上采样，以表达可通过桥跨河。水域使用现有展示数据，仅作约束近似，不是精确障碍物模型；建筑围墙等障碍尚未建模。
4. 对每个时间阈值选取 `格心时间 <= 阈值` 的单元，按行压缩成矩形后合并。当某一时段没有可达格心时，用精确可达路段的 2 m 几何走廊表示该小范围。细小路段和窄桥可能未落在可达格心上，始终可以通过独立的可达路段叠加层查看；走廊边缘不表示严格的秒级通行时间。
5. 所有时段使用同一时间场；在米制坐标下将外圈与已生成的内圈合并，再按网格步长加密边界后投影为经纬度，保持嵌套。圈面可包含孔洞和多个部分，不做会填平湖泊的大凸包。

面域由格心代表整格，存在约半格对角线的边界量化误差；2 m 走廊也属于面化近似。面积为米制投影中的几何面积，不是人口覆盖或可进入建筑面积。栅格之间及不同方式、阈值分析的分辨率可能不同，不应将细小面积差异解释为测绘精度。

设施数仅判断其点是否落入近似面域。设施点源自真实 OSM 记录，尚未逐个求解到真实入口的网络旅行时间；右侧附近设施时间仍使用已标注的直线距离估算。

## 模块与测试

- `py/prepare_accessibility.py`：原始路网预处理及来源清单。
- `py/accessibility.py`：规则、接入、最短时间、部分路段截断、点阵时间场、圈面及 JSONL 常驻计算进程。
- `server/accessibility.js`：参数验证、队列上限、超时、进程生命周期及 HTTP 接口。
- `src/App.vue`、`src/mapScene.js`：输入、地图起点、请求状态、结果失效、圈面/道路、统计及 GeoJSON 导出。

小型解析网络测试覆盖中部起点、部分道路、单行及逆向单行、步行双向、精确路口、接入时间、断开组件、水域隔断、速度上限、重叠长度去重、圈面有效和嵌套、非法输入。HTTP 测试覆盖请求格式、参数、请求大小和 Python 缺失恢复。真实武汉路网及浏览器检查另保存在 `tmp/` 下。
